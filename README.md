# Лісовий архів: Telegram-бот для порад звірів

Telegram-бот для Мишки-шкряботушки. Звірі надсилають боту документи з порадами (PDF, Word, txt), а бот запам'ятовує їх, відповідає на запитання звірів **лише за цими документами** і завжди вказує, з якого документа взяв пораду. Стандартні документи вже лежать у «Лісовому архіві» (папка `initial_docs`) і завантажуються при запуску.

Стек: Python, aiogram, PostgreSQL, SQLAlchemy (async), LLM через [Groq](https://groq.com), Docker Compose.

## Швидкий старт

Потрібні лише Docker і Docker Compose.

```bash
git clone <URL_РЕПОЗИТОРІЮ>
cd <ПАПКА_РЕПОЗИТОРІЮ>
cp .env.example .env
# відкрий .env і встав свої токени (див. нижче)
docker compose up --build
```

Це все: однією командою піднімаються база даних і бот, документи з `initial_docs` імпортуються автоматично. Повторний запуск не створює дублікатів.

### Змінні оточення

Усі токени передаються через змінні оточення (файл `.env`, шаблон у `.env.example`).

| Змінна | Призначення |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота від [@BotFather](https://t.me/BotFather) |
| `GROQ_API_KEY` | Ключ API для роботи з LLM від [console.groq.com](https://console.groq.com) |
| `POSTGRES_USER` | Ім'я користувача бази даних PostgreSQL (для Docker Compose) |
| `POSTGRES_PASSWORD` | Пароль користувача бази даних PostgreSQL (для Docker Compose) |
| `POSTGRES_DB` | Назва бази даних PostgreSQL (для Docker Compose) |
| `DATABASE_URL` | Повний рядок підключення до бази даних у форматі `postgresql+asyncpg://user:password@host:port/dbname` |

## Що вміє бот

| Команда / дія | Результат |
| --- | --- |
| текстове повідомлення | сприймається як питання; бот відповідає за документами й вказує джерело |
| файл `.pdf`, `.docx`, `.txt` | бот читає документ, визначає тему й місце, зберігає його в архів |
| `/start`, `/help` | привітання й інструкція |
| `/docs` | список усіх чинних документів архіву |
| `/mydocs` | власні документи звіра з можливістю видалити |

Бот працює лише в особистих повідомленнях, відповідає українською.

## Як це працює

### Відповідь на запитання

1. Бот шукає в чинних документах поради за питанням. Беруться документи **всіх** звірів, не лише того, хто питає.
2. Пріоритет за специфічністю: **конкретне місце (рукавичка) → частина лісу → загальне**. Загальна порада згадується додатково, але на питання про конкретне місце передусім даються поради саме для нього.
3. Під кожною порадою бот додає джерело, яке береться з бази, а не з тексту моделі:

   `📄 Джерело: «Назва» (Локація: …, Автор: …, дата)`

   Для документів архіву автор — «Лісовий архів».
4. Якщо звір не назвав місця, бот перепитує, про яку рукавичку чи частину лісу йдеться.
5. Якщо для названого місця окремої поради немає, бот дає пораду для частини лісу або загальну й прямо каже, що спеціальної поради для цього місця немає.
6. Якщо відповіді немає в жодному документі: «Цього в документах немає. Спробуй завантажити відповідний документ».
7. У запит до моделі додаються останні 5 повідомлень цього звіра (історія кожного звіра окремо). Порадами вважаються лише документи, а не попередні відповіді бота.

### Додавання документа

1. Бот перевіряє файл: підтримуваний формат, є текст. Інакше відповідає: «Не можу прочитати цей файл. Надішли PDF, Word або txt із текстом», і нічого не зберігає (це стосується фото, архівів, порожніх файлів і сканів без тексту).
2. Якщо точно такий вміст уже є в архіві: «Цей документ уже є в архіві».
3. LLM визначає тему документа й місце **з тексту** (назва файлу лише підказка).
4. Якщо місце з тексту неоднозначне, бот перепитує звіра й зберігає документ лише після відповіді. Поки відповіді немає, документ не зберігається, а на нове питання чи файл бот спершу нагадує про незавершене уточнення.
5. Документ зберігається з автором і часом подачі.
6. Якщо вже є чинний документ **з тією самою темою й тим самим місцем**, новий замінює його. Старий не видаляється, а стає неактивним, і звірі бачать лише чинний.

### Видалення

Звір може видалити лише власні документи (через `/mydocs`). Документи «Лісового архіву» видаляти не можна. Видалена версія, що замінила стару, не відновлює старий документ.

## Приклади діалогів

**Питання за документом**

```
Звір:  Які небезпеки поруч із рукавичкою під дубом?
Бот:   Небезпеки поруч із рукавичкою «Під дубом»:

       1. Яма – глибока яма від вивернутого дуба лежить за 30 кроків на північ. Восени її засипає листям, і її не видно, тому саме тоді вона найпідступніша.  
       2. Мисливці – мисливці ходять просікою на півночі по суботах.  
       3. Яструб – яструб вранці сидить на сухій верхівці дуба. Дрібним звірам тоді на галявину не виходити.  
        
       📄 Джерело: «Небезпеки поруч із рукавичкою Під дубом.txt» (Локація: рукавичка «Під дубом», Автор: Лісовий архів, 19.10.2026)
```

**Питання без місця**

```
Звір:  Які небезпеки?
Бот:   🌲 Хм, а про яку саме частину лісу чи рукавичку йдеться? Уточни місце, щоб я міг дати точну пораду!
```

**Немає відповіді**

```
Звір:  Як приготувати борщ?
Бот:   Цього в документах немає. Спробуй завантажити відповідний документ!
```

**Файл, який неможливо прочитати**

```
Звір:  <надсилає фото>
Бот:   Не можу прочитати цей файл. Надішли PDF, Word або txt із текстом.
```

## Структура проєкту

```text
forest-bot/
├── src/
│   ├── bot/
│   │   ├── handlers/      # Обробники повідомлень (питання, завантаження файлів, команди)
│   │   └── middlewares/   # Проміжні шари (сесії БД тощо)
│   ├── core/              # Конфігурація та налаштування підключення до БД
│   ├── models/            # SQLAlchemy моделі таблиць (Document, MessageHistory тощо)
│   ├── services/          # Бізнес-логіка, робота з Groq API та RAG
│   ├── __main__.py        # Точка входу для запуску бота
│   └── states.py          # FSM стани (очікування локації тощо)
├── initial_docs/          # Початкові документи «Лісового архіву», що імпортуються при запуску
├── .env                   # Локальні змінні середовища
├── .env.example           # Шаблон змінних оточення
├── docker-compose.yml     # Конфігурація Docker Compose (бот + PostgreSQL)
├── Dockerfile             # Інструкція з контеїнеризації бота
├── requirements.txt       # Залежності Python
└── README.md
```

## Обмеження

- **Ліміти Groq API:** Безкоштовний рівень Groq має ліміти на запити й токени. Для аналізу береться початок документа (до 4000 символів), тож дуже довгі документи аналізуються за початком тексту.
- **Ймовірнісні результати:** Тема й місце документа визначаються за допомогою LLM, тому для одного й того самого тексту результат у теорії може дещо відрізнятися між запусками.
- **Імпорт з локальної папки:** Google Диск або інші сховища не синхронізуються автоматично — початковий архів один раз імпортується з папки `initial_docs/` при запуску.
- **Логіка заміни версій:** Попередня версія документа в коді шукається за збігом теми та локації (а також перевіряється назва файлу), щоб оновлювати актуальні дані в архіві.
- **Поведінка при недоступності Groq:** Якщо API Groq тимчасово недоступне або виникає помилка мережі, бот логує помилку та надсилає користувачу ввічливе повідомлення-заглушку про те, що лісові стежки наразі заплуталися і варто перепитати пізніше.
